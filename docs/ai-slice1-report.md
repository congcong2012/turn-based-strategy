## 2. 行为开关（`AiProfile` 11 字段）

| 字段 | 含义 | easy | normal | hard |
| --- | --- | :---: | :---: | :---: |
| `noisy` | 带噪随机（弱档） | ✅ | — | — |
| `focusFire` | 集火残血权重 | 0.15 | 0.15 | 0.6 |
| `cohesion` | 抱团（v1 遗留） | 0 | 0 | **0**（已判定有害，见 §4） |
| `lookaheadK` | 前瞻候选数 | 0 | 5 | 12 |
| `deployPlan` | 部署阵容 | 随机 | 刀/枪/刀 | 刀/枪/刀 |
| `v2` | v2 语义：有动作就做（不因负分过手） | false | false | **true** |
| `smartProduce` | 生产按"每千军费战力 + 克制 + 占领手缺口" | false | false | **true** |
| `economy` | 据点收入的时间价值 | 0 | 0 | **3** |
| `threat` | 预计承受伤害的零和惩罚 | 0 | 0 | **0**（暂缓，见 §4） |
| `defend` | 敌方占领进度的紧急度 + 王城警报 | 0 | 0 | **6** |
| `repair` | 残血驻守己方据点的补给价值 | 0 | 0 | **8** |
| `counter` | 出兵时按对敌阵平均伤害加权 | 0 | 0 | **1** |
| `scoreAware` | 临近回合上限按 GDD 9.2 计分 | false | false | **true** |

**easy / normal 的所有 v2 开关恒为 0/false** —— 两档行为与 v1 逐字一致（既有 200+ 单测零改动通过即为证据）。

**评估器结构**（`src/ai/evaluate.ts`）：`基础项（v1，逐字保留） + v2 开关项（默认关闭）`。
每个 v2 项都必须是**零和**的（交换双方归属后分数仍互换），单测里有一条专门的对称性断言守住它。

## 3. 单项消融（真实地图，16 局/项，vs `normal`）

| 单项开关 | 胜率 | 结论 |
| --- | ---: | --- |
| `economy = 3` | **81.3%** | **倒挂的解药** —— 经济/扩张是真实地图的胜负手（与 AI-1 诊断一致） |
| `defend = 6` | **75.0%** | 明显利好：会打断敌方占领、会解王城之围 |
| `v2`（有动作就做） | 56.3% | 小幅利好 |

| **完整档（去威胁）** | **87.5%** | 采用 |

## 4. 被否决/暂缓的方案（都有数据支撑）

1. **`cohesion`（抱团）从困难档移除**。它是 v1 困难档在真实地图上倒挂的元凶之一：主动惩罚"离开己方重心"，等于阻止 AI 分散占点。切片 0 已证（hard 11.7%），切片 1 正式删除。
2. **`threat`（威胁图）暂缓到切片 2**。三组数据：`threat=3` 单项 0/16；温和档 `threat=0.5` 62.5%（不如不加的 68.8%）；`evaluate` 里的净暴露量级可到 ±5000 分，远超材料总分。结论：静态评估做不好风险判断，交给切片 2 的**真搜索**（2 层 beam 极小极大，对手的实际回手会在叶评估里自然体现）。开关保留、有单测、评估台可复现该消融。
3. **`economy=5`（更贪的经济）** 反而只有 50% —— 权重过大会让全军脱离战斗去跑图，3 是当前最优。
4. **生产策略不做"越贵越优先"的反面极端**：v1 的 `cost×0.15` 让重骑兵（600 分）永远压过刀盾兵（150 分）；v2 改成"每千军费战力 + 克制 + 占领手缺口"，但单项消融显示它只算中性（50%）—— 保留是因为它同时修掉了三个明显错误（不看克制、不看占领手数量、把手头宽裕当加分），并为切片 5 的行为断言提供抓手。

## 5. 顺带修掉的四个结构性缺陷（都写进了代码注释）

| # | 缺陷 | 后果（实测） | 修法 |
| --- | --- | --- | --- |
| 1 | `wait` 的启发式分恒为 0 | 一旦开启威胁项，任何负分走位都被 `wait` 击败 → **AI 集体挂机，0/16** | v2 档把 `wait` 从候选中剔除（无其他动作时才允许） |
| 2 | "最优分为负就结束回合" | 本作里提前收手**没有任何收益**（未行动单位随后再无机会） | v2 档改为"有动作就做"（`actThreshold = -Infinity`） |
| 3 | 走位风险罚与走位收益同量级 | 罚分把一切走位打成负分 | `MOVE_RISK_FACTOR = 0.3`（风险全权重只在叶评估计） |
| 4 | 王城被占的警报分只有 1200 | 弱于丢一台重骑兵（4000），解围意愿不足 | `HQ_ALARM = 20000`（斩首 = 立即淘汰，必须压过材料） |

## 7. 兼容性

- 难度值域不变（`'easy' | 'normal' | 'hard'`）→ **PVE 存档、联机兼容性不受影响**（`pveStore` 只校验值域）。
- 未新增依赖；未触碰 `src/game/**`（内核）、`src/net/**`（联机）、`pveSession.ts`（会话驱动）。
- AI 仍是纯函数 + 无状态派生随机（同种子可复现，刷新页面后逐帧一致）。

## 8. 遗留项（进入切片 2）

1. **风险判断（威胁图）交给真搜索**：切片 2 的 2 层 beam 极小极大落地后，重新评估是否需要静态威胁项（预期不需要）。
2. **`expert` 档**：新增难度值需要在 `PROFILES`、`PveSetup`、`pveStore` 的 `DIFFICULTIES` 校验数组三处同步（否则新档存档会被判非法清档）。
3. **easy 档未动**：仍是"随机 + 25% 过手"，与 normal 的差距是 0% 胜率 —— 阶梯底部很稳，但玩家侧的"简单"体验是否够友好（是否过于废物）值得在切片 5 与 UI 文案一起看。
4. **E2E 与 4 人图**：`ancient_04`（3 个 AI）尚未跑过评估台，切片 4 一并补。
