## 明确不是问题（避免过度修改）

- **设置页很长**：信息密度合理、分组清楚，主按钮在底部符合常规，不需要压缩。
- **部署阶段自动对准己方区域**：意图是对的（否则"点了却说不在部署区"），问题只在 F1 的越界。
- **手机格子 15px**：24 列宽的图 + 390px 屏的必然结果；已有"移动/攻击再点一次确认"，
  硬放大反而会让玩家看不到全局。暂不动。
- **AI 一开局就"已确认"**：文案已经说明，属于可接受的信息。

## 修复记录

### F1 · 取景越界（已修）

`focusTiles()` 原本只做"把目标矩形摆到正中"，没有考虑目标贴着地图边缘的情况：
部署区在地图最上方，居中就意味着镜头越过上边缘、地图整体下沉。

改为**先居中、再收敛到地图边界**：

- 内容比视口大 ⇒ 偏移量夹在 `[视口 - 内容, 0]`，贴边、不留空；
- 内容比视口小 ⇒ 老实居中。

实测（同一脚本）：上方留白 316px → **0px**，地图底部超出 371px → 0px，整张图完整可见。

### F2 · 手机顶栏折行（已修）

顶栏原来是"一个 flex 平铺"，390px 下换行点不可控 —— 「退出对局」被单独挤到第二行。
改成三个逻辑分组（状态 / 徽章 / 操作），桌面端 `.hud-group { display: contents }`
保持逐字不变，≤560px 时每组各占一行：

```
回合 1 · 阶段 部署 · 当前 你（你）· 资金 4000
单人练习                     🎯 定位  📜 日志  🔊 音效  退出对局
```

换行只发生在分组之间，不会再出现孤零零一颗按钮；昵称过长会截断而不是顶开整行。

### F6 · 创建房间入口（已修）

- 房间码**留空**：主按钮直接显示「创建房间」，点击 = 随机码 + 进房，标题改为「加入 / 创建房间」。
- 填了码但**位数不对**：按钮保持禁用，并给一行提示「房间码需要 6 位（清空则可以创建新房间）」——
  刻意**不**把"填了一半"当成"要开新房"，否则会让人以为连上了朋友那一房。

### F7 · 首屏技术参数（已修）

未入房时不再渲染 `status-line`，改为一句「还没加入房间：填一个 6 位房间码加入朋友的局，
或直接点下面的「创建房间」开一局 —— 你会是房主。」
一旦开始连接（`connecting` / `failed` / 已入房）立刻恢复技术行 —— 出问题时仍然有据可查。

### F3 / F4 / F5（已修，均为一行改动）

见 CHANGELOG 的 `[未发布]` 段。
