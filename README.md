# 古代战棋 · 可联机回合制战略游戏

一款**纯静态、零服务器成本**的联机回合制战棋：好友打开一个网址、输入同一个 6 位房间码即可开局，**2–4 人**混战。
所有游戏逻辑跑在房主浏览器里，通过 WebRTC 直连同步，部署在 GitHub Pages 上。

**线上地址**：https://congcong2012.github.io/turn-based-strategy/
当前版本：**v1.1.0**（页脚会显示版本号 · 构建日期 · commit，变更记录见 CHANGELOG.md）

---

## 怎么玩

1. 打开上面的网址，落在**主页**：三个入口 = 联机对战 / 单人练习（离线打 AI）/ 规则速查（手机浏览器也可以，支持双指缩放）
2. 点「联机对战」→ 填昵称 → 输入 6 位房间码（或让房主点「复制邀请链接」，把带 room 参数的链接发给你）
   - 大厅右上角有「← 返回主页」，随时可以退回去看规则
   - 想只让好友进房可以设一个**房间密码**：邀请链接会自动带上密码，好友点开即自动填好
   - 出现「已加密」徽章时，手动输密码的一方必须和房主**完全一致**（大小写敏感）；不一致只会一直「等待对手」，不会报错
3. 所有人点「准备」→ 房主点「开始游戏」（房主可在大厅选地图，不选则按人数自动挑）
4. **部署阶段**：预算 3000、最多 4 个单位，点兵种再点己方半场放置
5. **行动阶段**：点己方单位 → 蓝格移动 / 红格攻击；站在据点上是「占领」，兵营可「生产」
6. **淘汰制**：攻陷某人的王城或将其全歼即淘汰该玩家，最后存活者获胜；打满 30 大回合则按分数判定

| 规则要点 | 数值 |
| --- | --- |
| 收入 / 回合 | 王城 1200 + 兵营 300×2 + 村落 400×N（基础 1800） |
| 兵营产能 | 每座每回合 2 个单位（出场位：兵营格 → 相邻空格 → 顺延） |
| 单位上限 | 每方 32 |
| 胜负 | 攻陷王城 / 全歼 / 30 回合计分 / 投降 |
| 兵种三角 | 长枪兵克骑兵 → 刀盾兵克长枪/弓兵 → 骑兵克弓兵/器械（详见站内「规则速查」） |

完整设计见 docs/gdd.md；不想翻文档就直接看站内的「规则速查」页（数据与对局取自同一份 JSON）。

## 主页的三个入口

| 入口 | 状态 | 说明 |
| --- | --- | --- |
| ⚔️ 联机对战 | 可用 | 2–4 人房间，房主权威，断线可重连 |
| 🏯 单人练习（PVE） | **可用** | 纯前端 AI 对手，完全离线：可选 1–3 个对手、我的阵营、难度（简单 / 普通 / 困难）；**刷新/关标签页后回来能接着打** |
| 📜 规则速查 | 可用 | 兵种 / 克制 / 地形 / 据点经济 / 胜负 / 操作，全部由 `src/data/*.json` 渲染 |

页脚还有「❤ 请我喝杯茶」：纯粹是鼓励，点开是收款码（静态图片，不加载任何第三方脚本）。游戏本身永久免费、无广告、无账号。

## 断线重连

- **你刷新页面**：自动回到原房间与对局，不需要重新输房间码（真实网络下的刷新重连有专门的 E2E 用例守着）
- **房主刷新**：房主回来后会从本地存档恢复整局并同步给你，期间你这边显示「房主已断线，游戏暂停」
- **对手掉线**：席位与部队都会保留；如果正好轮到他，房主可以点「跳过其回合」
- **点「离开/返回大厅」** 才会清掉房主侧的存档（刷新或关标签页不会，否则没法恢复）

**单人练习（PVE）同理**：刷新页面或关掉标签页再回来，进「单人练习」会**接着上一局继续打**；
只有点「退出对局」才清档。**打完之后刷新会回到设置页**，不会停在旧结算界面上。

## 连不上怎么办

界面右上角有**连接状态徽章**（连接中 / 已连接 / 等待对手 / 重连中 / 失败）。如果一直连不上：

1. **切换信令**：大厅里把 `MQTT` 换成 `Torrent`（或反过来）——两条公共信令通道，二者都免费；
2. **手动直连**（推荐，成功率最高）：大厅选「手动直连（备用）」→
   - 房主点「我是房主：生成邀请码」→ 复制连接码，用微信/QQ 发给好友；
   - 好友点「我是加入方：粘贴邀请码」→ 粘贴 → 「生成应答码」→ 把应答码发回房主；
   - 房主粘贴应答码 → 「完成连接」。之后一切照常（这条链路完全不依赖公共信令）。
   - 注意：手动直连**只支持 2 人**；4 人局请用公共信令。
3. **诊断信息**：页面底部「诊断信息」可一键复制（含房间码、信令、连接状态、最近错误），发给出问题的一方最快定位。

## 本地开发

```bash
npm install
npm run dev            # http://127.0.0.1:5173
npm test               # 单元测试（202 个）
npm run e2e            # 端到端测试（含真实 P2P、手动直连与移动端）
npm run build          # 类型检查 + 生产构建
npm run preview        # 预览构建产物
```

CI 只跑其中三条轨道（`local` / `mobile` / `preview`）并**阻塞部署**，用 `npm run e2e:ci` 可以本地复现；
`p2p` 与 `manual` 依赖真实打洞，只在本地发版时跑（见 docs/release-checklist.md）。

调试：

- 同一台机器上开两个标签页免网络调试：`?transport=local`（仅 DEV 生效）
- 线上排查：加 `?debug=1` 后可在控制台读到 `window.__atGame` 与 `window.__atBoard`
- 经济数值调整：改 `src/data/*.json`，再跑 `npx vitest run tests/unit/balance.test.ts` 看 30 回合资金曲线

## 部署

推送到 `main`/`master`/`workbuddy-edition` 会自动触发 `.github/workflows/deploy.yml`：
跑单测 → `npm run build` → **`e2e` job 跑三条 E2E 轨道（失败则不部署）** → 上传 `dist/` → 发布到 GitHub Pages。

> 仓库 Settings → Pages → Build and deployment → **Source 必须选 GitHub Actions**。
> 若选「Deploy from a branch」，Pages 会把仓库根目录当站点，直接返回源码版 index.html，表现为白屏。

构建产物用相对路径（base 为 `./`），换成任何仓库名都能直接跑，无需改配置。

## 技术栈

TypeScript + React 19 + PixiJS 8（棋盘渲染，动态分包）+ Vite 8；
网络用 Trystero（`@trystero-p2p/mqtt` 公共信令，备用 `torrent`）建立 WebRTC DataChannel；
测试用 Vitest + Playwright。**无后端、无数据库、无付费服务。**

架构与关键决策见 docs/architecture.md，通信协议见 docs/protocol.md，里程碑见 docs/tasks.md，
变更记录见 CHANGELOG.md。

## 发版

1. 改 `package.json` 的 `version`，在 `CHANGELOG.md` 顶部加一条（含验收记录表）
2. 按 **docs/release-checklist.md** 从头走一遍（静态检查 → 构建 → 4 条 E2E 轨道 → 子路径复现 → 13 项手测 → 跨网真人验收）
3. `git tag -a vX.Y.Z && git push origin vX.Y.Z`，等 CI 绿，打开线上地址确认页脚版本号一致

   把输出粘进 CHANGELOG 的「线上自检结果」

## 已知限制

- 一房 2–4 人（3 人以上自动使用四人地图「四战之地」）
- 房间密码可选；密码不一致时表现为互相看不见（连接层拒绝配对，不会有"密码错误"提示）
- 手动直连仅支持 2 人，且不使用房间密码（该链路不经过信令）
- 单人练习（PVE）是**自由混战**：不做组队（内核没有「队伍」概念）
- 单人对局存档是**单槽**：两个标签页同时开可能互相覆盖
- 3 方打四角图会空出一角：那里的王城/兵营变为中立，占领可得 +1800/回合，但**不会淘汰任何人**
- 依赖公共信令中转，配对偶尔需要几秒（信令抖动时可切 Torrent）
- 游戏内不做主机迁移（房主掉线只暂停等待）
- 暂无观战与回放（回放所需数据已预留：房主种子 + 完整状态）
